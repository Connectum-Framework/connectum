"@connectum/events-amqp": minor

fix: `AmqpAdapter()` validates its options when the adapter is created and throws an error that names the option, instead of failing later at `connect()` or `subscribe()` with an error from amqplib or the broker, or silently using another value. Rejected: a missing or non-object `options` argument (it used to fail with `Cannot read properties of undefined`), `exchangeType` other than `topic`, `direct`, `fanout`, `headers` (a typo such as `"TOPIC"` used to hang `connect()` in the retry loop, see the new troubleshooting entry), `consumerOptions.prefetch` that is not an integer from 0 to 65535, `queueOptions.messageTtl` and `maxLength` that are not non-negative integers, `recovery.jitter` and `publishRetry.jitter` outside 0 to 1, `recovery` or `publishRetry` that is neither a boolean nor an object, a `publishRetry.maxRetries` that is not a number, an `encode`/`decode` that is not a function, and a `contentType` that is not a string. Values with a documented fallback keep it (`publishTimeoutMs`, `recovery.initialConnectMaxRetries`, fractional or negative `maxRetries`). A configuration that passed one of the rejected values now fails at start-up.
