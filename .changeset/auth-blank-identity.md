"@connectum/auth": patch

fix(auth): an identity whose subject is empty, or holds no character once the control characters are removed, is no longer accepted by any auth interceptor, and the identity headers no longer carry such a subject. The control characters here are the ones the identity headers have always removed: U+0000-U+0008, U+000B, U+000C, U+000E-U+001F and DEL (U+007F). Tab, LF and CR are not among them. A subject of spaces or tabs is not affected, and a subject with other characters keeps its text: `a\x01b` stays `a\x01b` in the identity, and the header still carries `ab`.

Changed results, each as before -> now:

- `createAuthInterceptor`: a verifier that returns such a subject, before: the handler ran with that subject. With `propagateHeaders` on, an empty string was already refused by the header writer, but a subject of control characters only was written as an empty header and the call went through. Now: `Unauthenticated: Authentication failed` in every case, and the handler does not run.
- `createJwtAuthInterceptor`: a `sub` (or the claim named by `claimsMapping.subject`) of control characters only, before: accepted, with an empty subject header written when `propagateHeaders` was on. An empty `sub` was already refused. Now: `Unauthenticated: JWT missing subject claim`.
- `createSessionAuthInterceptor`: a `mapSession` result with such a subject, before: accepted as in `createAuthInterceptor` (an empty string only with `propagateHeaders` off). Now: `Unauthenticated: Session mapping failed`.
- `createInternalAuthInterceptor`: a trust source (`meshIdentityTrust`, `signedTokenTrust`, `sharedSecretTrust` or a custom one) that returns such a subject, before: accepted. The interceptor has no header propagation. Now: `Unauthenticated: Untrusted internal request`.
- `createGatewayAuthInterceptor`, subject: a standard `x-auth-*` subject was already refused. A subject under a custom `headerMapping` name that holds only control characters, before: accepted. Now: `Unauthenticated: Missing subject header from gateway`, as for the standard name.
- `createGatewayAuthInterceptor`, type: a type header that is empty, or under the standard name holds only control characters, before: the identity got an empty type. Under a custom name, a header of control characters only was kept as sent. Now: the header counts as absent and `defaultType` applies, for standard and custom names.
- `parseAuthHeaders`: a subject header of control characters only, before: returned an identity with an empty subject. Now: returns `undefined`. A type header of control characters only, before: type `""`. Now: type `"unknown"`, as for an empty type header.
- `setAuthHeaders`: a subject or type of control characters only, before: written as an empty header. Now: throws `UnsafeHeaderValueError` for `subject` or `type` (reason `empty`, as for an empty string) and sets no header. `propagateAuthHeaders` wraps that error in `ConnectError` `Unauthenticated: Authentication failed`, with the original error as `cause`.
- `sharedSecretTrust`, `meshIdentityTrust` and `signedTokenTrust`: a fixed `subject`, `type`, allowlist `principal` or issuer key (used as the subject without `claimsMapping.subject`) that is empty or made of control characters only, before: the factory returned a trust source. Now: it throws a `TypeError` that names the option. A value that is not a string, passed at run time, is refused the same way.
- `createClientGatewayInterceptor`: a `subject` of control characters only, before: the interceptor was created and sent an empty subject header. Now: it throws a `TypeError` naming the option when created. `createGatewayAuthInterceptor` with `propagateHeaders` and a `defaultType` of control characters only, before: created, and the type header was written empty. Now: the same `TypeError` at creation. An empty string was already refused in both places, with the same error.

**BREAKING** only for code that relied on a subject or type that is empty or made of control characters: a verifier, mapper or trust source that returned one, a trust option set to one, or a gateway that sent one. Such an identity had no usable subject. Give the identity a real subject, or reject the credential in your verifier. A gateway type header that is empty or made of control characters now yields `defaultType` instead of an empty type, and `createClientGatewayInterceptor` and `createGatewayAuthInterceptor` now refuse a control-character-only `subject` or `defaultType` when created. See the migration guide `auth-identity`.
