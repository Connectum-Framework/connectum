fix: the value a `fallback` handler returns must now be the response message of the called method. A plain object with that message's fields (the form the documentation shows) is turned into the message, so `handler: () => ({ items: [] })` works; a message made with `create(OutputSchema, ...)` is used as it is. A plain object is checked field by field before the message is built, because `create()` alone drops unknown keys and coerces wrong values (a number in a string field becomes `"5"`). `undefined`, `null`, a string, a key that is not a field, a value of another kind than its field takes (a number in a string field, a non-boolean in a bool field, a non-array in a repeated field, an enum name for an enum) and a number the encoder cannot write (a fraction in an int32, `NaN`) fail the call with a `TypeError` that names `createFallbackInterceptor`, the expected type and the path of the problem, instead of a `serialize binary: ...` text from the protocol layer. A field of a oneof is set as `{ case, value }` under the name of the oneof; the bare member name is refused. The forms are those of protobuf-es: a wrapper such as `StringValue` in a singular field outside a oneof is its bare value and a `Struct` is a plain JSON object. Behind the error handler the client receives `Internal: internal error` and `onError` sees the full text. On a client transport the handler's value used to be passed on without a check; a plain object with fields the response type lacks is now refused.
