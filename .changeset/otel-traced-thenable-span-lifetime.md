"@connectum/otel": minor
---

fix: `traced()` and `traceAll()` no longer end the span of a thenable that is not a native `Promise` the moment the function returns. A function that returns a query builder (Knex, a Mongoose `Query`, a superagent request) or any object with a `then` method used to get a span of zero duration that covered none of the work. The span now stays open until the thenable settles, a rejection marks it `ERROR` with the message, and the work that a lazy thenable starts inside its `then` runs with the span as the active span, so spans it starts are its children. The span also covers the time between the call and the first read; the event `connectum.result.read` marks where that idle time ends.

The caller receives the same object the function returned: `then` is replaced on the object itself while it is followed and put back when it settles, so its prototype and chain methods (`where()`, `limit()`) stay and a lazy thenable is still not started before it is read. Traced functions that return the same thenable one from another (a `traceAll` service over a `traceAll` repository) all end with it, up to eight layers; the spans past that end at once. The handlers of the caller get the receiver and all arguments the thenable passes and run in the context of the call to `then`. A rejection handler of the tracing reaches the original `then` only when the caller passed one, so a callback-style thenable that stays silent without a handler is not turned into an uncaught exception; for a thenable that returns a native promise the failure is read from that promise and passed on unchanged. A thenable that resolves with a native promise keeps the span open until that promise settles. A native promise made in another realm (a `vm` context) is now recognised as a promise. A frozen thenable ends its span at once.

**Observability change.** A thenable is followed through its `then`. A builder that the caller consumes another way (Mongoose `exec()`, `cursor()`, `clone()`; Knex `stream()`, `toSQL()`, `clone()`; superagent `end(callback)`), and an immutable builder whose chain methods return new objects, never calls the `then` that was replaced. Before this change such a call exported a span of zero duration at once. Now its span ends when the garbage collector collects the builder, with the start time as its end time (zero-length, as before) and the event `connectum.result.unread`. The moment is up to the collector, so the span appears late, and a process that exits first exports nothing. To get a span that covers the work of such a builder, await it inside the traced function (`traced(async () => await query.exec())`). A generator that is never iterated never ends its span. These changes make the change `minor` and not `patch`: spans of calls that used to be exported immediately can now appear late or not at all, and the duration of spans of thenables changes from zero to the time of the work.
