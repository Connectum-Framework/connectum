Thank you for your interest in Connectum! Contributions of every size are welcome: bug
reports, ideas, documentation, and code.

This file holds the general rules. The development details (setup, commands, checks, code
style, tests) live in the documentation, so that they are kept in one place:

## Code of Conduct

This project adheres to the [Contributor Covenant Code of Conduct](./CODE_OF_CONDUCT.md).
By participating, you agree to uphold its terms.

## Reporting Security Vulnerabilities

Do not report a suspected vulnerability in a public issue. Use the private route described in
[SECURITY.md](./SECURITY.md).

## Reporting Bugs

Use the bug report form when you open a new issue.

1. **Check existing issues.** The problem may already be known.
2. **Fill in the form.** It asks for the `@connectum/*` package versions, the runtime and its
   version, what happened and what you expected, a minimal reproduction, and the error
   output. A minimal reproduction is the most useful thing you can add.

## Suggesting Enhancements

Use the feature request form when you open a new issue.

1. **Check existing issues and the [ADRs](https://connectum.dev/en/contributing/adr/).** The
   idea may have been discussed already.
2. **Fill in the form.** It asks for the affected package and the version you use, the problem and use case, your
   proposed solution, and the alternatives and trade-offs you considered.

## Contributing Code

1. **Find an issue to work on.** Issues labeled `good first issue` or `help wanted` are a good
   start.
2. **Discuss before you start,** especially for a large change or a change to a public API.
3. **Keep the pull request focused** on one change, with its tests and the documentation it
   affects.
4. **Follow the pull request process** in [Pull Requests](https://connectum.dev/en/contributing/pull-requests):
   the pull request template, a [Conventional Commits](https://connectum.dev/en/contributing/commit-messages)
   title, a changeset when a published package changes, passing CI, and a maintainer's approval.

## Getting Help

- **[GitHub Discussions](https://github.com/Connectum-Framework/connectum/discussions):**
  questions and ideas.
- **GitHub Issues:** bugs and feature requests.
- **[SECURITY.md](./SECURITY.md):** anything that may be a vulnerability.

Maintainers volunteer their time: be patient, be clear, and search before you ask.
