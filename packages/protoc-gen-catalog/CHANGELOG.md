## 1.3.0

### Minor Changes

- [#331](https://github.com/Connectum-Framework/connectum/pull/331) [`e23d1f4`](https://github.com/Connectum-Framework/connectum/commit/e23d1f40e1877f5bb9d0603bed1e5d9cb986ad98) Thanks [@intech](https://github.com/intech)! - Catalogs generated by `protoc-gen-connectum-catalog` now type each request as `MessageInitShape<typeof RequestSchema>` instead of the full message. `context.call`, the server-stream call, and `send` on client-stream and bidi streams accept a plain object literal, which is checked against the schema (unknown fields, wrong `oneof` cases and wrong map values are rejected), as well as an object built with `create()`. Responses are unchanged.
  
  Breaking at the type level only, and shipped as `minor` on purpose: all `@connectum/*` packages share one fixed version group, so `major` would bump every package to 2.0.0. Breaking for code that reads the request type of a regenerated catalog as a full message: the slot is `MessageInit<T>`, so `$typeName` is optional on it and it is no longer assignable to `MessageShape<typeof RequestSchema>`. Take the full-message type from the schema (`MessageShape<typeof RequestSchema>`) or normalise a value with `create(RequestSchema, request)`. Catalogs generated by an earlier version keep working: they still require a full message until they are regenerated.

- [#647](https://github.com/Connectum-Framework/connectum/pull/647) [`b42f9ca`](https://github.com/Connectum-Framework/connectum/commit/b42f9ca105e071a2f672318a36dc9e8112e6d6b6) Thanks [@intech](https://github.com/intech)! - feat: `protoc-gen-connectum-catalog` refuses a repeated `output_file` option and puts the `@generated` marker first. `opt: [output_file=a.ts, output_file=b.ts]` used to write only `b.ts` with no message; it now fails with `output_file given more than once ("a.ts", "b.ts")` and writes nothing. The `// @generated by protoc-gen-connectum-catalog vX.Y.Z. DO NOT EDIT.` line was printed below the import block, where tools that skip generated files do not look for it; it is now the first line of `catalog.gen.ts`. Give `output_file` once; regenerate to get the moved marker (nothing else in the file changes).

- [#647](https://github.com/Connectum-Framework/connectum/pull/647) [`b42f9ca`](https://github.com/Connectum-Framework/connectum/commit/b42f9ca105e071a2f672318a36dc9e8112e6d6b6) Thanks [@intech](https://github.com/intech)! - feat: `protoc-gen-connectum-catalog` refuses a `target` other than `ts`. The README has always said the catalog is TypeScript only, but the standard `target` option of `@bufbuild/protoplugin` was accepted: `target=js` and `target=dts` wrote a transpiled `catalog.gen.js` (no `declare module "@connectum/core"` augmentation) or `catalog.gen.d.ts` (every service typed `any`), and a `buf.gen.yaml` without a `target` got both files and no `.ts`, so every `ctx.call` key was silently untyped. All of these now fail with `target "js+dts" is not supported: the catalog is TypeScript only ... Use opt: [target=ts]`, and nothing is written. Add `target=ts` to the plugin's `opt` in `buf.gen.yaml` (the Quick Start already does); if you imported `catalog.gen.js` or `catalog.gen.d.ts`, import `catalog.gen.ts` (or its `.js` specifier through `import_extension=.js`) instead.

## 1.0.0

### Minor Changes

- [#152](https://github.com/Connectum-Framework/connectum/pull/152) [`21deccd`](https://github.com/Connectum-Framework/connectum/commit/21deccda4e401b044c5886cd22fdc65a4aad6837) Thanks [@intech](https://github.com/intech)! - feat(protoc-gen-catalog): new Buf/protoc plugin that generates the service catalog

  New package `@connectum/protoc-gen-catalog` — the `protoc-gen-connectum-catalog`
  plugin emits one `catalog.gen.ts` per buf module containing a runtime
  `serviceCatalog` object and the `@connectum/core` `ConnectumCallMap` /
  `ConnectumStreamMap` augmentation that types `ctx.call` / `ctx.stream`.

  Built on `@bufbuild/protoplugin`. Generated files carry the mandatory
  `import type {} from "@connectum/core";` (so the augmentation merges across
  packages), use the configured `import_extension` (`.js` recommended), classify
  methods via `DescMethod.methodKind` (kebab stream kinds), and include only
  files-to-generate. Requires `strategy: all` in `buf.gen.yaml`. `output_file`
  option supported (absolute / `..`-traversal paths rejected); empty input emits a
  valid empty catalog.

### Patch Changes

- [#159](https://github.com/Connectum-Framework/connectum/pull/159) [`66164ac`](https://github.com/Connectum-Framework/connectum/commit/66164acd3709fd1e1ec61ab12142b46e5dedb9bb) Thanks [@intech](https://github.com/intech)! - fix: preserve the `node:` protocol prefix on builtin imports

  tsup strips the `node:` prefix from builtin imports by default (`removeNodeProtocol: true`). The bare forms (`crypto`, `fs`, `http2`, …) are valid Node aliases, but the `node:` prefix is the portable specifier across runtimes — Deno resolves builtins prefix-first (bare forms are not guaranteed), and prefix-only builtins like `node:test` have no bare alias at all. Every package now sets `removeNodeProtocol: false`, so the published artifacts keep the prefix on every builtin import for maximum cross-runtime portability (Node / Bun / Deno). No runtime behavior change on Node. (`@connectum/testing` already carried this fix.)
